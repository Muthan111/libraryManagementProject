Library Management Infrastructure Documentation

How Docker, CI/CD, observability, MySQL, and Redis connect to the backend in this project.

Docker Docker Compose CI/CD Grafana Prometheus Loki MySQL Redis
NameDocker

Description

Docker packages the backend and frontend into repeatable container images. The backend image uses a Node 20 Alpine build stage, runs npm run build, then copies dist into a smaller production image that starts with node dist/src/main. The frontend image builds the Vite app and serves the generated static files with Nginx.

How It Is Connected

docker-compose.yml builds the backend from backend/Dockerfile as the libraryapp service and maps container port 3000 to host port 3000. The NestJS app listens on port 3000 in backend/src/main.ts. The frontend service is built from frontend/Dockerfile and depends on libraryapp.

backend/Dockerfile -> libraryapp container -> NestJS app on :3000 frontend/Dockerfile -> library-frontend container -> Nginx on :80 mapped to localhost:5173

How To Handle It Carefully

  • Keep secrets out of Dockerfiles; this project expects runtime values from backend/.env.prod.
  • Rebuild images after changing dependencies, build scripts, or compiled backend source.
  • Check that backend/Dockerfile start command matches the actual Nest build output before deploying.
  • Use production dependency installation in runtime images, but verify native packages still work on Alpine.
NameDocker Compose

Description

Docker Compose starts the local multi-container stack. It defines the frontend, backend, MySQL, Prometheus, Grafana, Loki, and Redis services in one file so they share service names on the Compose network.

How It Is Connected

The libraryapp service reads ./backend/.env.prod, waits for the mysql healthcheck, and connects to MySQL with DB_HOST=mysql. Redis is available by service name redis, Prometheus scrapes libraryapp:3000, and Loki is addressed from the backend as http://loki:3100/loki/api/v1/push.

docker compose up --build libraryapp -> mysql, redis, loki prometheus -> libraryapp:/metrics grafana -> prometheus and loki

How To Handle It Carefully

  • Run Compose from the repository root so relative paths like ./backend/.env.prod and ./prometheus.yml resolve correctly.
  • Do not remove named volumes such as mysql_data or redis_data unless you intentionally want to delete stored data.
  • Use docker-compose.test.yml for integration tests because it exposes MySQL on 3307 and Redis on 6380.
  • Make sure Docker Desktop is running before integration tests; the backend pretest script starts the test services if they are missing.
NameCI/CD

Description

GitHub Actions automates backend checks and backend image publishing. CI validates the backend on pushes to main and dev, and on pull requests to main. CD builds and pushes the backend Docker image when code is pushed to main.

How It Is Connected

.github/workflows/ci.yml uses backend/ as the working directory, installs dependencies with npm ci, runs linting, audits high severity dependencies, runs npm run test:ci, builds the project, and uploads backend/dist. .github/workflows/cd.yml logs into Docker Hub, builds backend/Dockerfile, tags it as ${DOCKER_USERNAME}/library-app:latest, and pushes it.

How To Handle It Carefully

  • Keep DOCKER_USERNAME and DOCKER_PASSWORD only in GitHub Secrets.
  • Remember that CI uses npm run test:ci, not the full integration suite, so database and Redis behavior still needs local or separate integration verification.
  • Avoid pushing broken main commits because CD publishes the latest backend image automatically.
  • Keep the Node version in CI aligned with the Docker image version, currently Node 20.
NameGrafana

Description

Grafana is the dashboard layer for viewing metrics and logs. In this stack it is exposed at http://localhost:3001 and depends on both Prometheus and Loki.

How It Is Connected

docker-compose.yml starts the grafana container from grafana/grafana, maps host port 3001 to container port 3000, sets the admin password to admin, and starts it after prometheus and loki. Prometheus provides backend metrics; Loki provides backend request logs.

How To Handle It Carefully

  • Change GF_SECURITY_ADMIN_PASSWORD before exposing Grafana beyond local development.
  • Add Prometheus and Loki data sources using their Compose service URLs: http://prometheus:9090 and http://loki:3100.
  • Do not treat dashboards as proof that the app is healthy unless Prometheus scraping and Loki log ingestion are both working.
  • Persist Grafana configuration if dashboards become important; the current Compose service does not define a Grafana volume.
NamePrometheus

Description

Prometheus collects numeric application metrics. The backend uses @willsoto/nestjs-prometheus and prom-client to expose default process metrics plus custom counters, gauges, and histograms.

How It Is Connected

MetricsModule registers the backend metrics endpoint at /metrics. prometheus.yml scrapes libraryapp:3000 every 15 seconds at the /metrics path. Middleware and services increment metrics such as http_requests_total, http_errors_total, auth_requests_total, book_operations_total, chatbot_requests_total, memory_usage_bytes, and cpu_usage_percent.

How To Handle It Carefully

  • Keep the /metrics route excluded from request-counting middleware to avoid noisy self-scrape metrics.
  • When adding metrics, register providers in backend/src/metrics/counter.ts before injecting them.
  • Use labels carefully; high-cardinality labels like raw URLs or user IDs can overload Prometheus.
  • If the backend service name or port changes, update prometheus.yml to match.
NameLoki

Description

Loki stores application logs. It is included as a local logging backend for Grafana and listens on port 3100.

How It Is Connected

LokiMiddleware runs for backend routes except selected endpoints like /metrics. It sends each request log to http://loki:3100/loki/api/v1/push with labels job="Library Management System" and level="info". The Compose service uses grafana/loki:2.9.0 and the local Loki configuration in loki-config.yaml.

How To Handle It Carefully

  • Use DISABLE_LOKI_LOGGING=true or NODE_ENV=test when tests should not depend on Loki.
  • Keep log messages free of passwords, tokens, and personal data because request logs are centralized.
  • Remember that http://loki:3100 works inside the Compose network; local host access uses http://localhost:3100.
  • If Loki is unavailable, the middleware logs an error but continues the request, so check logs when Grafana shows missing entries.
NameMySQL

Description

MySQL is the relational database for users, books, borrow records, authentication data, and TypeORM-managed entities. The production-like Compose service uses mysql:8.0 with persistent storage.

How It Is Connected

AppModule configures TypeORM with DB_HOST, DB_PORT, DB_USERNAME, DB_PASSWORD, and DB_NAME. In Compose, those values should point to mysql:3306. The backend service waits for the MySQL healthcheck before starting. Integration tests use a separate mysql_test service on host port 3307.

How To Handle It Carefully

  • Protect mysql_data; deleting the volume deletes the application database.
  • Review synchronize: true before production because TypeORM can modify schema automatically.
  • Keep local, test, and Compose database ports separate to avoid writing tests into development data.
  • Use strong passwords in backend/.env.prod and avoid committing real credentials.
NameRedis

Description

Redis stores session data, chatbot conversation history, and chatbot RAG chunks/vectors. The app uses the redis package and connect-redis.

How It Is Connected

backend/src/config/redis.ts creates a Redis client from REDIS_HOST and REDIS_PORT. createApp connects Redis during startup and passes the client into RedisStore for Express sessions. The chatbot conversation store reads and writes conversation keys, while RagService stores keys under patterns such as rag:book:<bookId>:*. Compose provides Redis as the redis service on port 6379; integration tests use redis_test on host port 6380.

How To Handle It Carefully

  • Use the correct host name for the environment: redis inside Compose, usually 127.0.0.1 for local test services.
  • Do not call resetRedis() outside test workflows because it flushes the active Redis database.
  • Monitor memory if many RAG chunks are indexed; vectors can grow quickly.
  • Keep redis_data if session and chatbot state should survive container restarts.
